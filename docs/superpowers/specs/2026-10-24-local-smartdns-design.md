# Локальные hosts для SmartDNS в doqd

## Цель и согласованный подход
Пользователь хочет использовать наш hosts вместо внешних гео-DNS. Собственный VPS не нужен. Имена из hosts получают перечисленные для них адреса прокси; все остальные имена обслуживаются обычными DoQ upstream. Прокси остаются сторонними.

Рассмотренные подходы: (1) нынешние гео-DNS с автоматической классификацией; (2) локальный hosts внутри doqd; (3) внешний DNS-сервис с правилами, как нынешний Cloudflare Gateway. Пользователь выбрал второй: он убирает зависимость от гео-DNS и внешнего управления правилами.

## Уточнения пользователя
Работа ведётся в отдельной Git-ветке feature/local-smartdns. Это замена архитектуры, не переключаемый режим. Гео-полоса удаляется полностью. Бывшие гео-DNS удаляются из дефолтов; вручную добавленные работают как обычные upstream.

## Первая версия
- Источник: /Library/Zapret2/artifacts/cloudflare-dns-20261022/combined-hosts.txt. Проверить перед импортом: 1025 уникальных имён, включая releases.openai.com; ws.chatgpt.com не добавлять.
- Поставлять снимок списка вместе с проектом, поддержать отдельный редактируемый hosts-файл. Не загружать обновления из сети автоматически.
- Совпадение точное, без учёта регистра и завершающей точки. Запись example.com не распространяется на произвольные поддомены. Несколько адресов одного имени сохраняются, дубликаты убираются.
- Локальный слой проверяется перед обычным DNS-кэшем. A/AAAA возвращают адреса соответствующего семейства. Если семейства в hosts нет — NOERROR с пустым ответом, а не NXDOMAIN и не запрос обычного адреса в интернете.
- Для перечисленных имён HTTPS/SVCB отвечают NOERROR без записей, чтобы реальные IP-подсказки и ECH не увели соединение мимо прокси. Не выставлять AD на локальных ответах. Остальные типы запросов идут обычным upstream.
- TTL локальных ответов 60 секунд. Перечитывание hosts атомарное по SIGHUP: ошибочный новый файл не заменяет рабочий. Старые запросы не должны возвращать устаревшую подмену после успешной перезагрузки списка. Клиентские кэши всё равно сохраняют ответы до TTL.
- Обычный резолвер, резервные upstream, объединение одинаковых запросов и существующий кэш сохраняются.
- Специальная категория geo-серверов, их классификация и переоценка удаляются. Нужен хотя бы один обычный upstream. Не добавлять в первую версию автоматическое переключение прокси по одному TLS-тесту: пользователь запросил адреса именно из файла, а TLS не доказывает работу сервиса.

## Интеграция и совместимость
Добавить настройку hosts без переключателя режимов и без legacy-гео-полосы. Удалить специальную конфигурацию geo/geo-domain и команды выбора гео-DNS. Установщики Keenetic и OpenWrt поставляют hosts и обычные upstream. Старые конфиги нельзя молча переписывать: сохранить резервную копию, перенос пользовательских серверов в обычные upstream должен быть явным. Невозможно автоматически превратить geo-domain без IP в hosts; такие записи требуют понятного сообщения. Статус показывает источник hosts, количество правил и обычные upstream.

Существующий Picker сохраняется: первым выбирается здоровый основной сервер с минимальным сглаженным временем ответа (EWMA). При задержке параллельно запускается следующая попытка. Это не рассылка каждого запроса всем серверам и не гарантия абсолютного минимума задержки на каждом запросе.

Для имён из hosts AAAA и HTTPS/SVCB не передаются наружу. Если IPv6-адресов в hosts нет, возвращается NOERROR/NODATA; HTTPS/SVCB также получают пустой ответ. Реальные IP-подсказки не выдаются. Эта гарантия относится к ответам doqd: собственный DNS клиента и его прежний кэш находятся за её пределами.


## Проверка
Тесты точного совпадения, регистра, дубликатов и нескольких IP; A/AAAA/HTTPS/SVCB, отсутствие AD; неизвестные имена и остальные типы уходят upstream; ошибки файла и атомарная перезагрузка; локальные ответы не перекрываются старым кэшем. Интеграционный DNS-тест по UDP/TCP, полный набор Go-тестов и race detector, проверка сборки целевых платформ.

## Границы
На этом этапе меняется и проверяется проект. Установку на домашний роутер проводить отдельным шагом после готового результата: сейчас рабочая схема использует native DoH и doqd удалён. Зависимость от доступности IP прокси и полноты списка остаётся. Новых доменов по догадке не добавлять.
