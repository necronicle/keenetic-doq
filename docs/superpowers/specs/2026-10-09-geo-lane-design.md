# keenetic-doq v0.4.0 — гео-полоса: закреплённый сервер обхода для геоблокированных имён

Дата: 2026-10-09. Статус: утверждено пользователем (дизайн по частям в
чате, спецификация — с добавлением раздела 8).

## Цель

Геоблокированные сервисы (ChatGPT, Claude, Gemini…) должны открываться
стабильно и быстро через сервер обхода, а обычные сайты — резолвиться
самым быстрым сервером, как сейчас.

Решения пользователя:

- обычные имена — самый быстрый сервер;
- геоблокированные — один раз надёжно выбранный сервер обхода, дальше
  только он; никакой ротации и прыжков между странами;
- геоблок определяется встроенным списком + своими доменами +
  автоопределением;
- закреплённый сервер меняется только при отказе (и вручную командой),
  выбор переживает рестарт.

## Почему (замеры 2026-10-09 на тест-роутере)

- doqd выбирал сервер по скорости DNS-ответа, а у серверов обхода
  быстрый DNS не значит быстрые прокси: comss отвечал первым (157 мс), а
  TLS до chatgpt.com через его прокси занимал 0,2–4,7 с против 0,13–0,15 с
  у dns-ai.
- Каждый сервер обхода отдаёт свой пул прокси; выбор «быстрейшего» на
  каждый запрос раздавал доменам одного сайта адреса из разных пулов
  (разные страны), а при подстраховке менял пул посреди сессии.
- Серверы сами отдают мёртвые и медленные прокси. У geohide
  `159.194.200.33` стабильно даёт TLS ~3,1 с. Узел dns-ai
  `186.246.48.217` в 13:44 сменил пул и начал отдавать для chatgpt.com
  `191.44.41.215`, который не принимает даже TCP. doqd пропускал их
  клиентам вслепую.

## 1. Конфиг и состояние

Новые ключи `geo` и `geo-domain`; остальные (`listen`, `upstream`,
`fallback`, `bootstrap`, `cache_size`, `min_ttl`, `max_ttl`, `log`) — без
изменений по синтаксису.

```
listen 192.168.1.1:5354

# Серверы обхода: геоблокированные имена идут только в один — закреплённый.
geo quic://geohide.ru
geo quic://dns.dns-ai.ru

# Обычные резолверы: обычные имена идут в быстрейший из них и серверов обхода.
upstream quic://dns.quad9.net
upstream quic://p0.freedns.controld.com

# Свои геоблокированные домены (с поддоменами) сверх встроенного списка.
geo-domain example.ai
```

- `geo` — гео-полоса; из этих серверов выбирается закреплённый, остальные —
  запасные по рейтингу.
- `upstream` — быстрая полоса. Кандидаты быстрой полосы — `upstream` и
  `geo` вместе; выбор быстрейшего — существующий `Picker` без изменений
  логики.
- `fallback` — как сейчас: спрашивается, только когда отказали все
  остальные; TTL ответа ≤ 60 с.
- Дефолты: `geo` = geohide, dns-ai; `upstream` = Quad9, ControlD
  `p0`; `fallback` нет. Первая строка любого из ключей `geo`/`upstream`/
  `fallback` отменяет дефолты всех трёх (как сейчас для двух).
- Конфиг обязан содержать хотя бы один `geo` или `upstream`. Без `geo`
  гео-полоса выключена, doqd — обычный быстрый DoQ-форвардер.
- `geo-domain` — домен, совпадение по суффиксу по границе метки
  (`example.ai` покрывает `x.example.ai`, но не `badexample.ai`).

Состояние выбора — `/opt/var/lib/doqd/geo.state` (JSON): закреплённый
сервер, время закрепления, рейтинг с итогами последней оценки. Пишется
только при смене выбора (атомарно: `.new` + rename). Выученные
автоопределением имена — только в памяти.

Снимок для CLI — `/tmp/doqd.state.json` (tmpfs): демон пишет его раз в
30 с и сразу при смене закреплённого. Содержит полосы, закреплённый,
рейтинг, пулы с состоянием адресов, число выученных имён, время снимка.

### Миграция (install.sh, одним релизом с бинарником)

- `upstream` с известными серверами обхода (`geohide.ru`, `dns.dns-ai.ru`,
  `dns.comss.one`) → `geo`. comss при этом остаётся удалённым, если
  `drop_comss` из 0.3.5 его убирает (порядок: сначала существующие
  миграции, потом переименование).
- `fallback quic://dns.quad9.net` и `fallback quic://p0.freedns.controld.com`
  → `upstream`.
- Прочие строки пользователя не трогаются.
- Комментарии-шапки блоков переписываются под новые ключи.
- Каталог `/opt/var/lib/doqd` создаётся инсталлером.

## 2. Выбор и закрепление сервера обхода

Оценка запускается: при старте, если `geo.state` нет или закреплённого
нет среди `geo` в конфиге; по `doqd geo reselect` (SIGUSR1 демону); при
отказе закреплённого (ниже). Периодической переоценки нет.

Оценка каждого `geo`-сервера (все параллельно, общий предел 15 с):

1. Пробные домены: `chatgpt.com`, `claude.ai`, `gemini.google.com` (A).
2. Подмена: ответ сверяется с ответом быстрой полосы без `geo`-серверов
   (только `upstream`, при их отсутствии — `fallback`). Пересечение по
   адресам → для этого домена сервер не обходит. Если сверять не с чем,
   проверка пропускается и любой ответ с адресами считается подменой.
3. Отпечаток пула сервера: все адреса A/AAAA и цели CNAME из ответов на
   пробные домены, для которых есть подмена.
4. Проверка прокси: TCP+TLS на `<адрес>:443` с SNI соответствующего
   пробного домена, 3 попытки на адрес, таймаут 2 с; считается
   рукопожатие TLS (сертификат не проверяется — прокси может отдавать
   свой).

Рейтинг: (1) охват — число пробных доменов с подменой и хотя бы одним
живым прокси, больше — лучше; (2) медиана TLS по живым прокси, меньше —
лучше; (3) при разнице медиан < 20 % — порядок в конфиге. Сервер без
охвата в рейтинг попадает последним и закреплённым не становится, если
есть хоть один с охватом.

Победитель закрепляется; рейтинг и отпечатки всех серверов сохраняются.
Пока идёт первая оценка, гео-полоса использует первый живой `geo` из
конфига (временно, без записи на диск).

Отказ закреплённого:

- три запроса к нему подряд кончились ошибкой или таймаутом; или
- все адреса его пула мертвы три цикла проверки подряд (раздел 4).

При отказе doqd сразу переключается на следующий по рейтингу сервер,
здоровый на последней оценке, и в фоне запускает полную переоценку;
результат записывается в `geo.state`. Сам на прежний сервер не
возвращается — только через `reselect`. Если здоровых запасных нет,
остаётся на текущем и продолжает проверки.

Разовая ошибка закреплённого на конкретном запросе (до порога отказа):
этот запрос отвечает следующий по рейтингу `geo`, ответ кешируется с
TTL ≤ 60 с. Все `geo` недоступны: устаревший ответ из кеша (RFC 8767, как
сейчас), иначе ответ быстрой полосы с TTL ≤ 60 с.

В фоне в остальное время проверяются только DNS-живость закреплённого
(существующий health-check) и его прокси.

## 3. Классификатор

Порядок для имени запроса:

1. Встроенный список + `geo-domain` (суффикс по границе метки) → гео.
   Встроенный список (начальный, в коде): `openai.com`, `chatgpt.com`,
   `oaistatic.com`, `oaiusercontent.com`, `sora.com`, `anthropic.com`,
   `claude.ai`, `claude.com`, `claudeusercontent.com`, `gemini.google.com`,
   `aistudio.google.com`, `generativelanguage.googleapis.com`,
   `notebooklm.google.com`, `x.ai`, `grok.com`.
2. Выученные имена (в памяти, LRU до 20 000): «гео» — до рестарта;
   «обычное» — 6 часов, потом перепроверка.
3. Неизвестное имя: запрос в быструю полосу и параллельно закреплённому.
   Если ответ любого из них попал в отпечаток пула любого `geo`-сервера
   (адрес или цель CNAME) → гео: клиенту ответ закреплённого, имя
   выучено как гео. Иначе → обычное: клиенту ответ быстрой полосы, имя
   выучено как обычное.
   Ожидание ответа закреплённого ограничено min(3×RTT, 1 с), не меньше
   300 мс; не успел — клиенту ответ быстрой полосы, имя не выучивается.

Все типы записей гео-имени идут только в закреплённый. Неизвестное имя с
типом не A/AAAA (HTTPS, SVCB, прочие) сначала классифицируется
внутренним A-запросом по правилу 3, затем маршрутизируется.

Если закреплённый отдал для гео-имени адреса вне своего отпечатка, они
добавляются в его отпечаток.

При смене закреплённого из кеша сбрасываются все записи, полученные
гео-полосой.

## 4. Здоровье прокси (только гео-полоса)

- Таблица адресов: пул закреплённого + все адреса из его ответов.
- Проверка раз в 30 с: TCP+TLS на :443 с SNI пробного домена (для
  адреса, впервые увиденного в ответе на имя, — SNI этого имени),
  таймаут 2 с, не больше 4 проверок одновременно.
- Состояния: мёртвый — 2 неудачи подряд; медленный — медиана TLS по
  последним 5 замерам > 1 с и > 3× лучшей медианы в пуле; здоровый —
  иначе; мёртвый оживает после первой удачи.
- Фильтр ответа: A/AAAA мёртвых и медленных адресов удаляются, если
  остаётся хотя бы один здоровый. Иначе ответ отдаётся как есть.
- Новый адрес в ответе отдаётся сразу и проверяется вне очереди; оказался
  мёртвым — записи кеша с ним сбрасываются.
- TTL ответов гео-полосы ограничен 300 с.

## 5. CLI и логи

- `doqd list` — две секции: `GEO` (закреплённый помечен `*`, у каждого:
  alive/down, rtt, `proxies N/M ok`, медиана TLS) и `FAST` (как сейчас);
  `fallback` — с пометкой. Данные о прокси — из снимка; если снимка нет
  (демон не запущен) — только живые DoQ-пробы, как сейчас.
- `doqd geo` — рейтинг с охватом по пробным доменам, пул каждого сервера
  с состоянием адресов, число выученных гео-имён, время оценки.
- `doqd geo reselect` — SIGUSR1 демону, ждёт в снимке новую оценку
  (до 30 с), печатает рейтинг.
- `doqd add --geo <url>`; `doqd add-domain <домен>`,
  `doqd remove-domain <домен>` — правка конфига + рестарт, как `add`.
- `doqd status` — строка `geo: pinned <host> since <time>, proxies N/M
  healthy`.
- Лог `info`: смена закреплённого (с причиной), прокси умер/ожил,
  результат оценки. `debug`: выученные имена.

## 6. Структура кода

- `internal/geo/list.go` — встроенный список, матчер по суффиксу.
- `internal/geo/classifier.go` — выученные имена, отпечатки, решение.
- `internal/geo/evaluate.go` — оценка и рейтинг (зависит от интерфейсов
  `Exchanger` и `TLSProber`).
- `internal/geo/proxyhealth.go` — таблица адресов, цикл проверок, фильтр.
- `internal/geo/pin.go` — закрепление, отказ, `geo.state`.
- `internal/geo/lanes.go` — `Exchanger`, маршрутизирующий запрос в полосу;
  `resolver.Resolver` получает его вместо `Picker`.
- `internal/cache` — пометка записей полосой и сброс по пометке/адресу.
- `internal/config` — ключи `geo`, `geo-domain`, новые дефолты.
- `internal/cli` — команды раздела 5, снимок.
- `install.sh` — миграция раздела 1.
