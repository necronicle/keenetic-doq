самого doqd); лицензия — GPL-3.0; README — русский основной + английский
`README.en.md`; вывод утилиты — английский.

## 1. CLI-утилита (подкоманды doqd)

Один бинарник. `doqd` без аргументов — демон, как сейчас; флаги `-c`,
`-version` сохраняются и работают как раньше. `doqd <подкоманда>` — режим
утилиты. Диспетчер по `os.Args[1]` в `cmd/doqd/main.go`, логика подкоманд —
в новом пакете `internal/cli`.

Общее для всех подкоманд:

- флаг `-c <path>` действует и в режиме утилиты (по умолчанию
  `/opt/etc/doqd.conf`);
- вывод на английском; ошибки — на stderr, код выхода 0/1;
- живая проверка апстрима = реальный DoQ-запрос через существующий
  `upstream.DoQ` (запрос `keenetic.com. A`, таймаут 5 секунд), меряется RTT;
- рестарт демона = запуск `/opt/etc/init.d/S56doqd restart`, затем проверка
  `... check` на `alive`. Если init-скрипта нет (запуск не на роутере) —
  предупреждение `restart skipped: init script not found`, конфиг всё равно
  правится, код выхода 0.

### doqd list

Читает конфиг, пробует все апстримы параллельно, печатает нумерованный
список: URL, `alive`/`down`, RTT для живых. Внизу — `listen` из конфига и
состояние демона (pid или `not running`).

### doqd test <url>

Валидация URL (тот же парсер, что у демона: схема `quic://`, порт по
умолчанию 853) + живой запрос. Конфиг не трогается. Код выхода 0 — сервер
ответил, 1 — нет (в выводе причина: имя не резолвится, таймаут рукопожатия,
ошибка TLS…). Используется инсталлером и годится для ручной проверки любого
сервера.

### doqd add <url> [--force]

1. Валидация URL; дубликат (уже есть в конфиге) — отказ, код 1.
2. Живая проверка; провал — отказ с подсказкой про `--force`
   (`--force` пропускает только провал проверки, не валидацию URL).
3. Строка `upstream <url>` дописывается в конфиг: после последней строки
   `upstream`, а если их нет — в конец файла. Остальные строки, включая
   комментарии и неизвестные ключи, сохраняются байт в байт.
4. Рестарт демона + проверка alive.

Если конфиг-файла нет, он создаётся с текущими дефолтами (как их отдаёт
`config.Default()`) плюс добавляемый апстрим; `listen` при создании берётся
из дефолта — предупреждение, что его надо проверить.

### doqd remove <номер|url>

Аргумент — номер из `doqd list` (1-based) или точный URL. Удалить последний
оставшийся апстрим не даёт (отказ, код 1). После удаления — рестарт.

### doqd status

- демон: pid по `/proc/*/comm == doqd` (или чтение cmdline), исключая
  собственный процесс; uptime процесса;
- слушает: значение `listen` из конфига;
- регистрация: `ndmc -c 'show ip name-server'` (fallback `ndmq`), ищем в
  выводе адрес из `listen`; если ndmc/ndmq недоступны — строка
  `registration: unknown (ndmc not found)`;
- сквозной тест: обычный DNS-запрос `keenetic.com. A` средствами miekg/dns
  на `<host из listen>:53` — проверяет путь через штатный ndnproxy; на
  не-роутере может честно показать ошибку, это нормально.

Каждая строка независима: недоступность одного источника не валит остальные.

### Редактирование конфига

`internal/cli` правит конфиг построчно (read → modify → атомарная запись
через временный файл + rename в том же каталоге). Никакой пере-сериализации:
нетронутые строки сохраняются как есть. Юнит-тесты на add/remove с
комментариями, пустыми строками и неизвестными ключами.

## 2. Установка одной командой

```sh
curl -fsSL https://raw.githubusercontent.com/necronicle/keenetic-doq/main/install.sh | sh
```

- `install.sh` и `uninstall.sh` переезжают из `deploy/` в корень репозитория;
  каталог `deploy/` упраздняется.
- Скрипты самодостаточны: шаблоны `doqd.conf` и `S56doqd` встроены heredoc-ами
  (сейчас надо скачивать три файла — это и мешало одной команде).
- Бинарник качается из GitHub Releases latest под архитектуру
  (`opkg print-architecture`, как сейчас) и сверяется с `SHA256SUMS` из того
  же релиза (`sha256sum -c` по нужной строке). Нет sha256sum в системе —
  предупреждение, установка продолжается.
- Режим `--local <binary>` сохраняется (пока репозиторий приватный и для
  оффлайн-установки).
- Логика LAN-IP (br0, отказ от loopback), регистрация `ip name-server`,
  `system configuration save`, порт 5354 — без изменений.
- В конце инсталлер печатает шпаргалку: `doqd status`, `doqd add quic://…`.
- Существующий конфиг при переустановке не перезаписывается (как сейчас).

## 3. README

`README.md` (русский, основной) + `README.en.md` (английский), взаимные
ссылки в первой строке. Структура обоих:

1. Что это: DoQ рядом со штатными DoT/DoH; схема потока; порт 53 не
   трогается, `opkg dns-override` не нужен, соседние проекты (Z2K и пр.)
   не страдают.
2. Требования: Keenetic с Entware, поддерживаемые архитектуры.
3. Установка одной командой (+ `--local` для оффлайна).
4. Управление апстримами: `doqd list/test/add/remove/status` с примерами
   вывода.
5. Конфигурация: таблица ключей `/opt/etc/doqd.conf`.
6. Проверка работы: dig напрямую и через :53, `show ip name-server`,
   tcpdump udp/853.
7. FAQ/диагностика: почему comss первым (ТСПУ и AdGuard), почему порт 5354
   (avahi), почему LAN-IP (KeeneticOS отвергает loopback), «сервер не
   отвечает» → `doqd test`.
8. Удаление.
9. Сборка из исходников.
10. Ограничения: только клиентский DoQ, без фильтрации; doqd слушает только
    LAN-адрес.

Бейджи CI и последнего релиза. Текущий README перерабатывается в эту
структуру, живые примеры вывода берутся с тест-роутера.

## 4. Обвязка публичного репозитория

- `LICENSE` — GPL-3.0.
- `CHANGELOG.md` — формат Keep a Changelog: задним числом v0.1.0, затем
  v0.2.0.
- Release-workflow дополнительно публикует `SHA256SUMS` по трём бинарникам.
- Шаблоны issues (`.github/ISSUE_TEMPLATE/`): bug report (модель роутера,
  архитектура, версия, вывод `doqd status` и логов) и feature request.
- Метаданные репозитория: description, topics (keenetic, dns, doq,
  dns-over-quic, entware, router).
- Явно НЕ входит (YAGNI): DoH/DoT-апстримы, метрики, веб-интерфейс,
  интерактивный инсталлятор (можно докрутить позже поверх утилиты),
  CONTRIBUTING/CoC (добавим по мере появления контрибьюторов).

## 5. Тестирование и приёмка

- Юнит-тесты: `internal/cli` (редактирование конфига, парсинг аргументов,
  выбор по номеру/URL, запрет удаления последнего апстрима); существующие
  тесты не ломаются; `go vet` чист; CI зелёный.
- Живой тест на роутере 192.168.1.1: uninstall старой версии → установка
  одной командой (пока приватный — эквивалент через `--local`/GITHUB_TOKEN) →
  `doqd status`/`list` → `doqd test quic://dns.quad9.net` → `add` → проверка
  резолва → `remove` → uninstall → повторная установка. Продакшен-состояние
  роутера в конце восстановлено (doqd установлен и работает).
- Релиз v0.2.0: тег, релиз с тремя бинарниками и SHA256SUMS.
- Публикация: перевод репозитория в public — только после явного
  подтверждения пользователя, это последний шаг милстоуна.
