## 2. Найденные баги и фиксы

### 2.1 `doqd add` убивал сам себя (и оставлял демона выключенным)

`rc.func` останавливает демона через `killall $PROCS`, а процесс утилиты
называется так же — `doqd`:

```
~ # doqd add quic://dns.quad9.net
probing quic://dns.quad9.net ... OK (225 ms)
added to /opt/etc/doqd.conf (upstream #3)
restarting the daemon ... exit=143     ← SIGTERM самому себе
Terminated
~ # doqd status
daemon:          not running
```

Фикс: перезапуск больше не идёт через init-скрипт. Утилита шлёт SIGTERM
самому демону, ждёт его смерти и запускает его же argv (из
`/proc/<pid>/cmdline`) под `setsid`. Демон отличается от утилиты по
argv[1]: у демона его нет или он начинается с `-`.

### 2.2 Неизвестная подкоманда поднимала демона

`doqd frobnicate` уходил в демон-режим и падал с `bind: address already in
use`. Фикс: в утилиту уходит любой аргумент, не начинающийся с `-`.

## 4. Демон, перезапущенный утилитой, живёт правильно

- переживает закрытие ssh-сессии (новое подключение: `uptime 7s`, тот же
  pid) — заслуга `setsid`;
- виден штатному init-скрипту: `S56doqd check` → `alive`.

## 6. Edge-кейсы

```
doqd add quic://dns.comss.one       → error: upstream ... is already in the config      (exit 1)
doqd add quic://no-such-host.invalid→ FAIL ... not added — re-run with --force          (exit 1)
doqd add --force quic://unfiltered.adguard-dns.com → FAIL, adding anyway (--force)      (exit 0)
doqd remove 1 (последний апстрим)   → error: refusing to remove the last upstream       (exit 1)
doqd test https://wrong.example     → error: scheme must be quic://                     (exit 1)
doqd frobnicate                     → unknown command + usage                           (exit 2)
```
