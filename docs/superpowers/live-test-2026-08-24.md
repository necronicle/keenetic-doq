# Живой тест keenetic-doq на роутере 192.168.1.1 (aarch64), 2026-08-24

Версия: live-test (пред-v0.1.0). Все проверки пройдены.

## 1. Loopback как name-server — НЕ принимается

```
ndmc -c 'ip name-server 127.0.0.1:5354'
Dns::Manager error[22544486]: invalid IP address: 127.0.0.1.
```

→ инсталлер переведён на LAN-адрес (br0):

```
ndmc -c 'ip name-server 192.168.1.1:5354'
Dns::Manager: Name server 192.168.1.1:5354 added, domain (default).
```

## 2. Порт 5353 занят avahi (mDNS) — дефолт перенесён на 5354

```
udp 0.0.0.0:5353  11133/avahi-daemon
```

## 3. Установка install.sh --local — успех, doqd alive

```
tcp 192.168.1.1:5354 LISTEN 9772/doqd
udp 192.168.1.1:5354        9772/doqd
```

## 4. Прямой запрос и кеш (с клиента LAN)

```
dig @192.168.1.1 -p 5354 keenetic.com   → 160 ms (живой, DoQ)
повтор                                   → 17 ms (кеш)
```

## 5. Сквозной путь через штатный ndnproxy :53

```
dig @192.168.1.1 doq-live-<rand>.example.com → NOERROR
show ip name-server → address: 192.168.1.1, port: 5354, global: 0
```

Порт 53 остался за ndnproxy (PID 820), Z2K-процессы живы — соседи не задеты.

## 6. Доказательство QUIC (tcpdump udp/853 на роутере)

Запрос свежего имени → двусторонний обмен с comss:

```
Out 88.87.93.11.52311 > 83.220.169.155.853  (×8)
In  83.220.169.155.853 > 88.87.93.11.52311  (×5)
ответ за 160 ms, status NOERROR
```

Одновременно видны односторонние ретраи к 94.140.14.141:853 (AdGuard) без
ответов — AdGuard DoQ/DoT блокируется ТСПУ на этом провайдере (подтверждено
и с мака: DoT tcp/853 тоже мёртв). Это работа health-check по down-апстриму;
failover отрабатывает штатно.

## 7. Перезагрузка роутера

После `system reboot`:

- `S56doqd check` → alive (автозапуск Entware);
- `show ip name-server` → 192.168.1.1:5354 на месте (конфигурация сохранена);
- сквозной резолв свежего имени через :53 → NOERROR;
- прямой запрос в doqd → ответы.
