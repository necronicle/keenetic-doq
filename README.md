**Telegram: [топик DoQ в @zapret2keenetic](https://t.me/zapret2keenetic/55256)** — вопросы, помощь с настройкой, обсуждение

DNS-over-QUIC (RFC 9250) для роутеров **Keenetic** и **OpenWRT**.

`doqd` — небольшой демон на роутере. Он принимает обычные DNS-запросы и
отправляет их на DoQ-серверы по зашифрованному каналу. Порт 53 doqd не
занимает: штатный DNS роутера остаётся на месте и передаёт запросы в doqd.

```
Keenetic:  клиенты → ndnproxy :53 → <LAN-IP>:5354 (doqd) ─┐
OpenWRT:   клиенты → dnsmasq  :53 → 127.0.0.1:5354 (doqd) ─┤
                                                           ├ геоблокированное имя → закреплённый сервер обхода (quic://)
                                                           └ остальные имена      → самый быстрый обычный сервер (quic://)
```

У doqd две полосы:

- **Гео-полоса.** Имена геоблокированных сервисов (ChatGPT, Claude, Gemini…)
  идут только на один закреплённый сервер обхода. Сервер обхода отдаёт
  адреса своих прокси. Все домены сервиса получают прокси одной страны.
- **Быстрая полоса.** Все остальные имена идут на самый быстрый живой обычный
  сервер. Серверы обхода их не получают.

> Данный проект предназначен для исследования сетевых протоколов и изучения работы DNS. Используется исключительно в учебных целях.

## Возможности

- DoQ-клиент по RFC 9250: QUIC-соединения живут долго, на каждый запрос —
  свой поток. Есть keep-alive и TLS-возобновление. ID запроса на проводе — 0.
- У сервера несколько адресов: doqd пробует их лесенкой. Мёртвый адрес не
  задерживает живой. Удачный адрес doqd запоминает.
- Гео-полоса. doqd один раз оценивает серверы обхода (`geo`): живость и
  скорость TLS до их прокси. Лучший сервер doqd закрепляет. Закреплённый
  сервер меняется только при отказе. Раз в 30 с doqd проверяет его прокси и
  убирает из ответов мёртвые и медленные.
- Быстрая полоса. Запрос идёт на самый быстрый живой сервер из `upstream`.
  Серверы `geo` в ней не участвуют. Если в конфиге нет ни одного
  `upstream`, обычные имена идут на серверы `geo`. Ответ SERVFAIL, REFUSED
  или с оборванной цепочкой CNAME (CNAME без адреса в конце) не выигрывает у
  полного ответа другого сервера. Если сервер молчит дольше ~3× своего
  обычного времени, doqd параллельно спрашивает следующий. Мёртвый сервер уходит в конец очереди.
  Резервные серверы (`fallback`) doqd спрашивает, только когда отказали все
  остальные.
- Если соединение перестало отвечать (например, после переподключения WAN),
  doqd заменяет его новым. Медленный ответ одного запроса соединение не рвёт.
- Кеш ответов по TTL с вытеснением LRU. Одинаковые одновременные запросы
  уходят наружу один раз. Если серверы недоступны или отвечают дольше 1,8 с,
  doqd отдаёт устаревший ответ из кеша (RFC 8767, до суток, с TTL 30 с).
- Управление в том же бинарнике: `doqd add/remove/list/test/status/geo`,
  `add-domain`/`remove-domain`. Файлы править не нужно. Перед записью в
  конфиг doqd проверяет сервер живым запросом.
- Статический бинарник без зависимостей. Корневые сертификаты встроены на
  случай, если в прошивке их нет.

## Требования

| | Keenetic | OpenWRT |
|---|---|---|
| Прошивка | KeeneticOS с [Entware](https://help.keenetic.com/hc/ru/articles/360000925139) | OpenWRT 24.10 или 25.12 с dnsmasq (стандартная сборка) |
| Скачивание | `curl` (`opkg install curl`) | `wget` из прошивки (uclient-fetch) или `curl` |
| Флеш | место в Entware (USB или встроенная память) | 4–5 МБ свободно на JFFS2/UBIFS, 9 МБ на ext4/f2fs; установщик проверит |
| Память | около 13–15 МБ RAM на демона | около 13–15 МБ RAM на демона |

На Keenetic busybox-`wget` собран без TLS и не открывает `https://`. Поэтому
нужен `curl`. Всё остальное для doqd и его скриптов есть в busybox.

Если Entware не устанавливается (сервер пакетов `bin.entware.net` обрывает
загрузку), возьмите офлайн-установщик из репозитория
[entware-offline](https://github.com/necronicle/entware-offline): официальный
установщик с пакетами внутри и с `curl`, сеть при установке не нужна.

Бинарник весит 7–8,5 МБ. JFFS2 и UBIFS на флеше роутеров сжимают файлы,
поэтому там он занимает меньше. Установщик для OpenWRT оценивает нужное
место до копирования. Если место всё же кончилось, установщик удаляет doqd
и возвращает dnsmasq в исходное состояние.

OpenWRT 24.10.8 и 25.12.5 проверены в эмуляторе QEMU на aarch64, mipsel,
mips64, mips64el и armv7. Сборки amd64, 386, riscv64 и armv5 проверены
запуском с DoQ-запросом. Сборка loong64 собрана, но не запускалась.

### Архитектуры

| Бинарник | Keenetic (Entware) | OpenWRT (`DISTRIB_ARCH`) |
|---|---|---|
| `doqd-linux-arm64` | `aarch64-*` | `aarch64_*` |
| `doqd-linux-mipsle` | `mipsel-*` | `mipsel_*` |
| `doqd-linux-mips` | `mips-*` | `mips_*` |
| `doqd-linux-armv7` | — | `arm_cortex-a*_vfp*`, `arm_cortex-a*_neon*` |
| `doqd-linux-armv5` | — | ARM без FPU: `arm_cortex-a7`, `arm_cortex-a9`, `arm_arm926ej-s`, `arm_arm1176jzf-s_vfp`, `arm_xscale` |
| `doqd-linux-amd64` | — | `x86_64` |
| `doqd-linux-386` | — | `i386_pentium4`, `i386_pentium-mmx` |
| `doqd-linux-mips64` | — | `mips64_*` |
| `doqd-linux-mips64le` | — | `mips64el_*` |
| `doqd-linux-riscv64` | — | `riscv64_*` |
| `doqd-linux-loong64` | — | `loongarch64_*` |

Установщик выбирает бинарник сам. Если сборка `armv7` не запускается
(у процессора нет FPU), установщик берёт `armv5`.

Go не собирает программы под ARMv4 (`arm_fa526`), ARM big-endian
(`armeb_xscale`), PowerPC (`powerpc_*`) и ARC. На этих платформах doqd не
работает.

## Установка на Keenetic

Подключитесь к роутеру по SSH (Entware, порт 222) и выполните:

```sh
curl -fsSL https://raw.githubusercontent.com/necronicle/keenetic-doq/main/install.sh | sh
```

Установщик делает следующее:

1. Определяет архитектуру Entware.
2. Скачивает бинарник из релиза и сверяет SHA256.
3. Ставит `/opt/sbin/doqd`.
4. Пишет конфиг `/opt/etc/doqd.conf` с LAN-адресом роутера.
5. Пишет init-скрипт `/opt/etc/init.d/S56doqd` и запускает демона.
6. Регистрирует doqd в KeeneticOS: `ip name-server <LAN-IP>:5354`.

Существующий конфиг установщик не перезаписывает. Конфиги старых версий он
переводит на текущий формат. Повторный запуск ничего не ломает.

Без доступа к GitHub скопируйте бинарник на роутер и выполните:

```sh
sh install.sh --local ./doqd-linux-arm64
```

После установки выключите DoT и DoH в KeeneticOS. Иначе роутер не
спрашивает doqd (см. [ниже](#keenetic)).

## Установка на OpenWRT

Подключитесь к роутеру по SSH и выполните:

```sh
wget -qO- https://raw.githubusercontent.com/necronicle/keenetic-doq/main/install-openwrt.sh | sh
```

Установщик делает следующее:

1. Определяет архитектуру по `DISTRIB_ARCH` из `/etc/openwrt_release`.
2. Скачивает бинарник из релиза и сверяет SHA256.
3. Проверяет свободное место на флеше.
4. Ставит `/usr/sbin/doqd`.
5. Пишет конфиг `/etc/doqd.conf` (`listen 127.0.0.1:5354`).
6. Пишет init-скрипт procd `/etc/init.d/doqd`. procd перезапускает демона
   после любого сбоя.
7. Добавляет файлы doqd в список sysupgrade. Так doqd переживает обновление
   прошивки с сохранением настроек.
8. Запускает демона и ждёт, когда doqd ответит на запрос. **Если doqd не
   ответил, установщик останавливается, а dnsmasq работает со своими
   исходными серверами.** DNS роутера продолжает работать.
9. Делает doqd единственным сервером dnsmasq (подробно — в разделе
   [OpenWRT](#openwrt)).
10. Проверяет запрос через dnsmasq на порту 53. Если ответа нет, установщик
    возвращает dnsmasq в исходное состояние.

Без доступа к GitHub скопируйте бинарник на роутер и выполните:

```sh
sh install-openwrt.sh --local ./doqd-linux-mipsle
```

Повторный запуск обновляет doqd. Конфиг и исходные настройки dnsmasq
остаются.

## Как doqd встроен в DNS роутера

### Keenetic

Для KeeneticOS doqd — обычный DNS-сервер, прописанный вручную. Какой сервер
ответит клиенту, решает штатная логика роутера:

- **Включены DoT или DoH — роутер не спрашивает doqd.** По
  [справке Keenetic](https://support.keenetic.ru/ultra/kn-1811/ru/31543.html)
  все запросы тогда идут только на серверы DoT/DoH. DNS провайдера и
  серверы, прописанные вручную (в том числе doqd), не используются.
  Запасного переключения на них нет. Выключите DoT и DoH.
- **DoT и DoH выключены — запрос уходит сразу на все обычные серверы**: на
  doqd, на DNS провайдера и на другие серверы, прописанные вручную. Клиент
  получает самый быстрый ответ
  ([справка Keenetic](https://support.keenetic.ru/ultra/kn-1811/ru/22961.html)).

DNS провайдера можно оставить. Тогда часть ответов придёт от него, и заранее
не известно, какая. Чтобы все запросы шли через doqd, отключите DNS
провайдера:

1. В настройках подключения к интернету включите «игнорировать DNS
   провайдера». В CLI это `interface <имя-подключения> ip no name-servers`.
2. Выполните `system configuration save`.

После этого DNS роутера работает, только пока работает doqd.

Устройства с профилем интернет-фильтра (AdGuard DNS, Яндекс.DNS, SkyDNS)
спрашивают DNS фильтра, а не doqd.

### OpenWRT

На OpenWRT doqd стоит за dnsmasq. Установщик меняет в `/etc/config/dhcp`
(секция `dhcp.@dnsmasq[0]`) три вещи:

- `server 127.0.0.1#5354` — dnsmasq отправляет запросы в doqd.
- `noresolv 1` — dnsmasq не берёт DNS-серверы провайдера (WAN). Иначе
  dnsmasq отправлял бы каждый запрос на один из своих серверов, не
  обязательно на doqd
  ([man dnsmasq](https://thekelleys.org.uk/dnsmasq/docs/dnsmasq-man.html),
  `--strict-order`).
- `server /openwrt.pool.ntp.org/<bootstrap>` — имена серверов NTP идут на
  bootstrap-серверы обычным DNS. Причина ниже.

**Зачем обход для NTP.** После перезагрузки часы роутера могут отставать.
OpenWRT ставит часы по самому новому файлу в `/etc`
([sysfixtime](https://github.com/openwrt/openwrt/blob/main/package/base-files/files/etc/init.d/sysfixtime)).
Если часы отстают, сертификаты DoQ-серверов кажутся ещё не выданными. Тогда
doqd не может установить TLS-соединение. Без обхода NTP тоже спрашивал бы
doqd и не получил бы ответа: часы не исправились бы никогда. С обходом NTP
ставит часы, и doqd начинает работать сам. Так же поступает
[руководство OpenWRT](https://openwrt.org/docs/guide-user/base-system/dhcp_configuration)
(раздел «Race conditions with sysntpd»). Установщик берёт имена из
`system.ntp.server` и адреса из строк `bootstrap` в `/etc/doqd.conf`.

Исходное значение `noresolv` и добавленные записи установщик сохраняет в
`/etc/doqd/dnsmasq.saved`. Удаление возвращает `noresolv` и удаляет только
эти записи. Запись, которая была у dnsmasq до установки, остаётся.

**Другие серверы dnsmasq.** Если у dnsmasq уже есть серверы для всех имён
(их ставят https-dns-proxy, stubby, podkop и другие), установщик их не
удаляет. Он выводит предупреждение. `doqd status` показывает такие серверы
в строке `other DNS`. dnsmasq отправляет запрос на один из своих серверов,
поэтому часть запросов пройдёт мимо doqd. Чтобы все запросы шли через doqd,
удалите лишние серверы или прокси, который их добавил.

**AdGuard Home и другие DNS-серверы на порту 53.** Если dnsmasq не слушает
порт 53 (`dhcp.@dnsmasq[0].port` не 53), установщик предупредит об этом.
Тогда пропишите `127.0.0.1:5354` апстримом в этом DNS-сервере вручную.

**Обновление прошивки.** sysupgrade с сохранением настроек сохраняет
`/etc/config/dhcp`, где dnsmasq смотрит в doqd. Поэтому установщик
добавляет в `/lib/upgrade/keep.d/doqd` бинарник, init-скрипт, ссылки
автозапуска, конфиг и `/etc/doqd/`. После обновления doqd запускается сам.
Обновление без сохранения настроек удаляет doqd и возвращает стандартный
dnsmasq.

## Управление

Все команды работают одинаково на Keenetic и OpenWRT. Пути к файлам doqd
выбирает сам (см. [Конфигурация](#конфигурация)).

Список серверов с живой проверкой:

```sh
~ # doqd list
GEO — geo-blocked names go only to the pinned server, marked * (/etc/doqd.conf):
 * 1. quic://dns.bezmezhau.com                   alive  rtt 81 ms   proxies 2/2 ok, tls 220 ms
FAST — every other name goes to the fastest of these:
   2. quic://dns.quad9.net                       alive  rtt 249 ms
   3. quic://p0.freedns.controld.com             alive  rtt 122 ms
   4. quic://dns.nextdns.io                      alive  rtt 151 ms

listen: 127.0.0.1:5354   daemon: running (pid 3560)
```

Секция GEO — серверы обхода. Звёздочка отмечает закреплённый. Секция FAST —
обычные серверы: остальные имена идут на самый быстрый из них.
Резервные серверы doqd помечает `[fallback]`.

Закреплённый сервер, рейтинг и прокси:

```sh
~ # doqd geo
pinned:     quic://dns.bezmezhau.com (since 2026-10-17 01:00)
evaluation: 2026-10-17 01:00

RANKING (last evaluation):
 1. quic://dns.bezmezhau.com            coverage 7/7  proxies 2/2 alive  tls 220 ms

PINNED SERVER PROXIES (checked every 30 s):
  31.58.216.201                             healthy  tls 440 ms
  143.20.64.55                              healthy  tls 220 ms

learned geo-blocked names: 0
```

Прокси `slow` doqd не отдаёт клиентам, пока рядом есть здоровые.

`doqd geo reselect` оценивает серверы обхода заново сразу (ждёт до 45 с и
показывает новый выбор). `doqd add --geo` выбор не меняет: закреплённый
сервер переживает рестарт. Чтобы оценить новый сервер, выполните
`doqd geo reselect`.

Проверка любого сервера без изменения конфига:

```sh
~ # doqd test quic://dns.quad9.net
probing quic://dns.quad9.net
  bootstrap  2 address(es) from 1.1.1.1:53 over udp in 27 ms: 149.112.112.112, 9.9.9.9
  connect    149.112.112.112:853  OK in 113 ms
  query      keenetic.com A  answered in 47 ms
OK — answered in 188 ms
```

Добавление сервера. doqd сначала проверяет сервер. Мёртвый сервер doqd не
добавит (флаг `--force` отменяет проверку). Без флагов сервер попадает в
`upstream`. С `--geo` — в серверы обхода, с `--fallback` — в резервные.
После записи doqd перезапускает демона:

```sh
~ # doqd add --fallback quic://dns10.quad9.net
probing quic://dns10.quad9.net ... OK (273 ms)
added to /etc/doqd.conf as fallback #5
restarting the daemon ... alive (pid 3948)
```

Удаление — по номеру из `doqd list` или по URL. Последний сервер `geo` или
`upstream` удалить нельзя:

```sh
~ # doqd remove 5
removed fallback quic://dns10.quad9.net
restarting the daemon ... alive (pid 4016)
```

Свой геоблокированный домен (с поддоменами). Встроенный список остаётся:

```sh
~ # doqd add-domain example.com
~ # doqd remove-domain example.com
```

## Конфигурация

| | Keenetic | OpenWRT |
|---|---|---|
| Конфиг | `/opt/etc/doqd.conf` | `/etc/doqd.conf` |
| Бинарник | `/opt/sbin/doqd` | `/usr/sbin/doqd` |
| Init-скрипт | `/opt/etc/init.d/S56doqd` | `/etc/init.d/doqd` |
| Закреплённый сервер | `/opt/var/lib/doqd/geo.state` | `/etc/doqd/geo.state` |
| Журнал | не пишется | `logread -e doqd` |
| `listen` | `<LAN-IP>:5354` | `127.0.0.1:5354` |

Ключи конфига:

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `listen` | см. таблицу выше | адрес и порт doqd (UDP и TCP) |
| `geo` | `quic://dns.bezmezhau.com` | сервер обхода, строка на сервер. Геоблокированные имена идут только на закреплённый из них. Остальные имена эти серверы не получают. Первая строка `geo`, `upstream` или `fallback` отменяет значения по умолчанию всех трёх ключей |
| `upstream` | `quic://dns.quad9.net`, `quic://p0.freedns.controld.com`, `quic://dns.nextdns.io` | обычный DoQ-сервер, строка на сервер. Остальные имена идут на самый быстрый живой сервер из `upstream`. Без `upstream` они идут на серверы `geo` |
| `fallback` | нет | резервный DoQ-сервер. doqd спрашивает его, только когда отказали все `geo` и `upstream`. TTL его ответов не больше 60 с. Нужен хотя бы один `geo` или `upstream` |
| `geo-domain` | нет | свой геоблокированный домен (с поддоменами), строка на домен. Добавляется к встроенному списку. Удобнее `doqd add-domain` |
| `bootstrap` | `77.88.8.8`, `77.88.8.8:1253`, `8.8.8.8`, `1.1.1.1` | обычные DNS-серверы для адресов DoQ-серверов (на OpenWRT — и для имён NTP). Только IP, порт можно указать. doqd спрашивает все сразу. Если сервер молчит по UDP, doqd спрашивает его по TCP. Ответ кешируется на его TTL |
| `cache_size` | `4096` | максимум записей в кеше |
| `min_ttl` / `max_ttl` | `60` / `86400` | границы TTL в кеше, секунды |
| `log` | `info` | `debug`, `info`, `warn` или `error` |

Команды `doqd add`, `remove`, `add-domain` и `remove-domain` сами
перезапускают демона. После правки конфига вручную перезапустите демона:

```sh
/opt/etc/init.d/S56doqd restart    # Keenetic
/etc/init.d/doqd restart           # OpenWRT
```

## Проверка работы

`doqd status` проверяет всё сразу. Он отправляет запрос прямо в doqd и через
штатный DNS роутера на порту 53. Ещё он показывает закреплённый сервер
обхода и проверяет, что DNS роутера передаёт запросы в doqd.

Keenetic:

```sh
~ # doqd status
daemon:          running (pid 4572, uptime 4s)
listen:          192.168.1.1:5354 (udp+tcp)
geo:             pinned dns.bezmezhau.com since 2026-10-17 01:00, proxies 2/2 healthy
registration:    present in KeeneticOS name-servers
resolve via doqd: NOERROR, 42 ms
resolve via :53:  NOERROR, 1 ms
```

OpenWRT:

```sh
~ # doqd status
daemon:          running (pid 3560, uptime 10s)
listen:          127.0.0.1:5354 (udp+tcp)
geo:             pinned dns.bezmezhau.com since 2026-10-17 01:00, proxies 2/2 healthy
dnsmasq:         forwards to doqd (127.0.0.1#5354)
resolve via doqd: NOERROR, 0 ms
resolve via :53:  NOERROR, 0 ms
```

Строка `dnsmasq` на OpenWRT сверяет два места: `/etc/config/dhcp` и конфиг,
с которым dnsmasq работает сейчас (`/var/etc/dnsmasq.conf.*`).

Подробная проверка на Keenetic:

```sh
ndmc -c 'show ip name-server'        # регистрация, утилита есть всегда
tcpdump -ni any 'udp port 853'       # трафик DoQ; нужен пакет: opkg install tcpdump
```

Подробная проверка на OpenWRT:

```sh
uci show dhcp.@dnsmasq[0]            # server и noresolv
nslookup chatgpt.com 127.0.0.1       # ответ через dnsmasq и doqd
logread -e doqd                      # журнал doqd
```

С компьютера в той же сети (нужен `dig`):

```sh
dig @192.168.1.1 example.com           # через DNS роутера
dig @192.168.1.1 -p 5354 example.com   # прямо в doqd; только Keenetic, на OpenWRT doqd слушает 127.0.0.1
```

## FAQ

### Общие вопросы

**Почему такие серверы по умолчанию, а не AdGuard?** Bezmezhau DNS
(`quic://dns.bezmezhau.com`) — сервер обхода геоблокировок. Для ChatGPT,
Gemini, Claude и других сервисов, закрытых для региона, он отдаёт адреса своих
прокси. Поэтому геоблокированные имена идут только на него. Quad9, ControlD и
NextDNS таких адресов не знают и отдают настоящие. Остальные имена идут только на
эти три сервера, на самый быстрый: серверам обхода незачем видеть всё, что вы
открываете. У Cloudflare и Google DoQ нет. AdGuard DNS в ряде сетей РФ блокирует
ТСПУ — и по DoQ, и по DoT. Проверьте свои серверы: `doqd list` проверяет каждый
живым запросом. Недоступный сервер обхода работе не мешает: запросы его
обходят. Убрать его можно командой `doqd remove <номер>`.

**Геоблокированный сервис (ChatGPT, Gemini…) не открывается.** Выполните по
порядку:

1. Выполните `doqd geo`. Посмотрите закреплённый сервер, живость и TLS его
   прокси.
2. Если прокси мертвы, а замены нет, выполните `doqd geo reselect`.
3. Если домена нет во встроенном списке, добавьте его:
   `doqd add-domain <домен>`.
4. Перезапустите браузер на устройстве. Старые соединения и кеш устройства
   хранят прежние адреса.
5. Выполните `doqd status`. Строка `other DNS` значит, что у роутера есть
   другие DNS-серверы, и настоящий адрес может прийти мимо doqd. Как это
   исправить, сказано в разделе
   [Как doqd встроен в DNS роутера](#как-doqd-встроен-в-dns-роутера).

**Как doqd отличает геоблокированное имя от обычного?** По трём источникам:

- Встроенный список: OpenAI, Anthropic, Gemini/AI Studio, NotebookLM, xAI.
- Свои домены: `geo-domain` в конфиге или `doqd add-domain`.
- Автоопределение. Для неизвестного имени doqd смотрит ответ закреплённого
  сервера. Если в ответе адреса из пула прокси этого сервера, имя считается
  геоблокированным. Дальше оно идёт только на этот сервер.

Напрямую doqd классифицирует только A-запросы. Для AAAA, HTTPS и других
типов он сначала делает внутренний A-запрос. Выученное имя остаётся
геоблокированным до рестарта.

В HTTPS/SVCB-ответах для геоблокированных имён doqd удаляет подсказки
`ipv4hint` и `ipv6hint`. В них может быть настоящий адрес сервиса, и браузер
пошёл бы мимо прокси. Если на такой запрос не ответил ни один сервер обхода,
doqd отвечает пустым ответом (NODATA). Браузер тогда возьмёт адреса из A/AAAA.

Пул прокси растёт только от ответов на пробные домены: chatgpt.com,
sentinel.openai.com, tcr9i.chat.openai.com, auth.openai.com, claude.ai,
assets-proxy.anthropic.com, gemini.google.com. Иначе имя из списка, которое
сервер не подменяет (например, x.ai с адресами Cloudflare), затянуло бы в
гео-полосу все сайты Cloudflare. Обычные сайты получают настоящие адреса от
самого быстрого обычного сервера.

**Как doqd выбирает сервер обхода и почему не прыгает между ними?** При
первом запуске (и по `doqd geo reselect`) doqd оценивает каждый сервер `geo`:

- охват — сколько пробных доменов сервер подменяет живым прокси;
- медиана TLS-рукопожатия до его прокси.

Сначала doqd сравнивает охват, потом скорость. Серверы с медианой TLS в
пределах 20 % от лучшей считаются равными и сохраняют порядок из конфига.
Поэтому выбор не скачет из-за шума замеров. Сервер с неполным охватом
закрепляется, но оценка повторяется (1 мин, затем ×2 до 30 мин), пока не
вернётся сервер с полным охватом.

Закреплённый сервер меняется только при отказе:

- три ошибки подряд на A/AAAA (SERVFAIL и REFUSED тоже считаются, ошибки на
  HTTPS/SVCB — нет: geohide всегда сбрасывает такие запросы);
- или все его прокси мертвы три проверки подряд (проверка раз в 30 с).

Перед переключением doqd проверяет сеть запросом через быструю полосу. Если
молчит и она, виновата сеть, и закреплённый сервер остаётся. Оценка, где ни
один сервер ничего не обошёл (обычно нет интернета), не меняет прежний выбор
и `geo.state`. Она повторяется через 1 мин, 2, 4… до 30 мин. Повреждённый
`geo.state` запускает новую оценку.

Если прокси закреплённого сервера стал мёртвым или медленным, doqd сразу
удаляет из кеша ответы с ним. Условие: в ответе есть здоровый адрес того же
типа. Ответ, где плохи все адреса, фильтр отдаёт как есть.

**Серверы по умолчанию что-то фильтруют.** `dns.quad9.net` блокирует
вредоносные домены. ControlD `p0` и NextDNS без своего профиля
(`dns.nextdns.io`) не фильтруют ничего. Вариант Quad9 без
блокировок — `doqd add quic://dns10.quad9.net`, затем `doqd remove` для
`dns.quad9.net`. Если AdGuard у вас доступен — `quic://unfiltered.adguard-dns.com`.

**В `doqd list` сервер down с ошибкой `bootstrap lookup ...: no bootstrap
server answered`.** Сам DoQ-сервер может быть жив. doqd не узнал его адрес:
ни один bootstrap-сервер не ответил на обычный DNS-запрос ни по UDP, ни по
TCP. Если другие серверы живы, провайдер почти наверняка выбрасывает
DNS-запросы на порт 53 с именами сервисов обхода. Помогает bootstrap на
другом порту, у Яндекс DNS это 1253. В новых установках он уже есть. В
старом конфиге добавьте строку `bootstrap 77.88.8.8:1253` и перезапустите
демона. Проверка вручную: `nslookup <имя> 77.88.8.8` молчит, а
`doqd test quic://<имя>` после правки отвечает.

**В `doqd list` сервер down с ошибкой `dial ...: context deadline exceeded`
или `no address answered`.** Адрес сервера найден, но QUIC-соединение
(udp/853) не установилось. `doqd test quic://<имя>` покажет по шагам, какие
адреса пробовались. Если сервер работает из других сетей, его почти
наверняка блокирует провайдер. doqd это не исправит. На работу DNS это не
влияет: недоступный сервер уходит в конец очереди. Лишний сервер уберите:
`doqd remove <номер>`.

**Добавил сервер, а он down.** `doqd list` показывает живость и RTT каждого
сервера. `doqd remove <номер>` убирает лишний. `doqd add` сам проверяет
сервер и без `--force` не запишет мёртвый.

**Куда делся comss?** Его убрали из значений по умолчанию в 0.3.5. DNS у
comss отвечал быстро, но его прокси были самыми медленными: TLS до
chatgpt.com занимал от 0,2 до 4,7 с, через dns-ai — 0,13–0,15 с. Вернуть
comss можно: `doqd add --geo quic://dns.comss.one`.

**Куда делись geohide и dns-ai?** В 0.5.2 по умолчанию используется Bezmezhau DNS
(`quic://dns.bezmezhau.com`). Вернуть прежние серверы можно командами:
`doqd add --geo quic://geohide.ru` и `doqd add --geo quic://dns.dns-ai.ru`.

### Keenetic

**`ndmc: system failed [0xcffd0062]` / `Cli::Main: failed to initialize`, а
`doqd status` пишет `registration: NOT found` или `registration: unknown`.**
doqd установлен и работает. Так выглядит установка из шелла, открытого
командой `exec sh` внутри штатного CLI роутера (SSH на порт 22, логин
admin). Сессия CLI уже занята, и `ndmc` не может открыть вторую. Поэтому
установщик не смог прописать name-server. Наберите `exit`, чтобы вернуться к
приглашению `(config)>`, и выполните:

```
ip name-server <LAN-IP>:5354
system configuration save
show ip name-server
```

Эти же команды работают в Web CLI (`http://<адрес-роутера>/a`). `ndmc` и
`doqd status` нормально работают из сессии Entware (SSH на порт 222, логин
root). Пока регистрации нет, запросы идут мимо doqd.

**После перезагрузки роутера пропал интернет: IP пингуются, имена не
резолвятся, а `doqd list` пишет `lookup ... on 127.0.0.1:53: i/o timeout`.**
Это ошибка версий до 0.3.0. Обновитесь командой установки. С 0.3.0 doqd
узнаёт адреса своих серверов через `bootstrap`, мимо DNS роутера.

**После перезагрузки роутера doqd не поднимается.** С 0.2.5 демон ждёт
появления своего адреса. Если doqd всё равно не поднимается, выполните
`doqd status`. Если адреса из `listen` нет ни на одном интерфейсе, `doqd
status` скажет об этом прямо. Обычно LAN-адрес роутеру выдаёт вышестоящий
DHCP (режим Relay), и после перезагрузки адрес сменился. Задайте роутеру
постоянный LAN-адрес, исправьте `listen` в `/opt/etc/doqd.conf` и
зарегистрируйте doqd заново: `ip name-server <новый-адрес>:5354`.

**Почему порт 5354, а не 5353?** Порт 5353 на Keenetic занимает
avahi-daemon (mDNS).

**Почему LAN-адрес, а не 127.0.0.1?** KeeneticOS не принимает loopback в
`ip name-server` (`Dns::Manager: invalid IP address`).

**Как откатиться на 0.3.x?** Версии 0.3.x не знают ключи `geo` и
`geo-domain` и с конфигом 0.4.0+ не запустятся. Перед установкой старой
версии удалите `/opt/etc/doqd.conf`: установщик старой версии создаст свой.
Или исправьте конфиг вручную: строки `geo` переделайте в `upstream`, строки
`upstream` с Quad9 и ControlD — в `fallback`, строки `geo-domain` удалите.

### OpenWRT

**Установщик пишет `doqd ... did not resolve a test name`.** doqd установлен
и работает, но не получил ответ ни от одного DoQ-сервера. dnsmasq работает
со своими исходными серверами (при переустановке установщик возвращает их),
DNS роутера работает. Выполните `doqd list`: он покажет, какой
сервер недоступен и почему. Журнал: `logread -e doqd`. Исправьте причину и
запустите установщик снова.

**После перезагрузки DNS не работает несколько секунд.** Это нормально.
doqd стартует после сети, но WAN поднимается позже. Пока WAN не поднят, doqd
отвечает SERVFAIL. В эмуляторе doqd отвечал через 20 с после загрузки.

**Часы роутера ушли назад, и doqd не работает.** В журнале
(`logread -e doqd`) видна ошибка `x509: certificate has expired or is not
yet valid`. Установщик пропускает имена NTP мимо doqd, поэтому NTP сам
исправит часы, и doqd заработает. Если вы сменили серверы NTP после
установки, запустите установщик снова: он обновит обход. Если серверы NTP
заданы IP-адресами, обход не нужен.

**DNS роутера не работает, а скачать скрипт удаления нельзя.** Верните
dnsmasq его серверы вручную. Для этого интернет не нужен:

```sh
uci del_list dhcp.@dnsmasq[0].server='127.0.0.1#5354'
uci set dhcp.@dnsmasq[0].noresolv='0'
uci commit dhcp
/etc/init.d/dnsmasq restart
```

dnsmasq снова спрашивает DNS провайдера. Затем найдите причину:
`doqd list` и `logread -e doqd`. Удаление полностью — `uninstall-openwrt.sh`.

**Куда пишет журнал?** В системный журнал: `logread -e doqd`. Все строки
doqd там с уровнем `daemon.err`, потому что doqd пишет в stderr. Настоящий
уровень — в поле `level=` каждой строки.

**Можно ли поставить doqd рядом с https-dns-proxy, stubby или podkop?** Да,
но тогда у dnsmasq несколько серверов. dnsmasq отправляет запрос на один из
них, и часть запросов пойдёт мимо doqd. Чтобы все запросы шли через doqd,
отключите другой прокси или удалите его сервер из
`dhcp.@dnsmasq[0].server`.

**Почему 127.0.0.1, а не LAN-адрес?** doqd спрашивает только dnsmasq на том
же роутере. Адрес 127.0.0.1 недоступен из сети, поэтому doqd никто не
спросит напрямую.

## Удаление

Keenetic:

```sh
curl -fsSL https://raw.githubusercontent.com/necronicle/keenetic-doq/main/uninstall.sh | sh
```

Скрипт снимает регистрацию name-server, останавливает и удаляет демона.
Конфиг `/opt/etc/doqd.conf` остаётся.

OpenWRT:

```sh
wget -qO- https://raw.githubusercontent.com/necronicle/keenetic-doq/main/uninstall-openwrt.sh | sh
```

Скрипт сначала возвращает dnsmasq исходные `server` и `noresolv`. DNS
роутера при этом продолжает работать. Затем скрипт останавливает и удаляет
демона, init-скрипт и список sysupgrade. Конфиг `/etc/doqd.conf` остаётся.

Нужен Go 1.26 или новее.

```sh
sh scripts/build-all.sh dist          # все архитектуры в каталог dist
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -ldflags "-s -w" -o doqd ./cmd/doqd   # одна архитектура
```

Параметры каждой архитектуры (GOARM, GOMIPS и другие) — в
`scripts/build-all.sh`.

## Ограничения

- Шифруется участок «роутер → внешний сервер». Его видит провайдер. Внутри
  LAN устройства спрашивают роутер обычным DNS: doqd не принимает
  DoQ-подключения от клиентов. Штатные DoT и DoH в KeeneticOS работают так
  же.
- doqd ничего не фильтрует и не блокирует. Он возвращает ответ сервера как
  есть. Исключение — мёртвые и медленные прокси сервера обхода: их фильтр
  убирает.
- doqd не слушает WAN. На Keenetic он слушает LAN-адрес, на OpenWRT —
  127.0.0.1.
